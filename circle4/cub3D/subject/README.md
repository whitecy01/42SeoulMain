# cub3D — 요구사항 정리

> 42Seoul Circle 4 · *My first RayCaster with miniLibX* (Subject Version 11.0)
> 본 문서는 `cub3d.pdf` 과제 명세를 한국어로 정리한 요구사항 문서입니다.

## 1. 개요

Wolfenstein 3D(최초의 FPS)에서 영감을 받은 프로젝트. **레이캐스팅(ray-casting)** 원리로 미로 내부를 1인칭 시점의 "현실적" 3D 그래픽으로 표현한다. C 언어와 수학을 도구로 사용해 윈도우·색상·이벤트·도형 채우기 등 그래픽 기술을 익힌다.

## 2. 공통 규칙 (Common Instructions)

- **C 언어**, **Norm 준수**(보너스 파일/함수도 norm 검사 대상, 위반 시 0점).
- 예기치 못한 종료(segfault, bus error, double free 등) 금지 → 프로젝트 0점.
- 힙 할당 메모리는 모두 적절히 해제, **메모리 누수 금지**.
- `Makefile`: `cc` + `-Wall -Wextra -Werror`, 불필요한 relink 금지. 규칙 `$(NAME)`, `all`, `clean`, `fclean`, `re`, **`bonus`** 포함.
- 보너스는 `_bonus.{c/h}` 파일에 분리, mandatory와 별도 평가.
- libft 사용 시 `libft` 폴더에 소스+Makefile 복사 후 프로젝트 Makefile이 먼저 컴파일.

## 3. Mandatory part

| 항목 | 내용 |
|------|------|
| 프로그램명 | `cub3D` |
| 인자 | `*.cub` 형식의 맵 파일 |
| 허용 함수 | `open`, `close`, `read`, `write`, `printf`, `malloc`, `free`, `perror`, `strerror`, `exit`, `gettimeofday`, math 라이브러리 전체(`-lm`), MinilibX 전체 |
| libft | 허용 |

**제약 사항**
- **MiniLibX 필수 사용**(OS 설치본 또는 소스). 소스 사용 시 libft와 동일한 규칙 적용.
- 윈도우 관리가 매끄러워야 함(다른 창 전환, 최소화 등).
- 벽이 향하는 **방향(North/South/East/West)에 따라 다른 텍스처** 표시.
- 바닥(floor)과 천장(ceiling)을 **서로 다른 두 색**으로 설정 가능.
- 조작:
  - **←/→ 방향키**: 좌우로 시점 회전.
  - **W/A/S/D**: 미로 안에서 시점 이동.
  - **ESC**: 윈도우 닫고 깔끔하게 종료.
  - 윈도우 프레임 **빨간 X 클릭**: 깔끔하게 종료.
  - MiniLibX의 **image** 사용 강력 권장.

### `.cub` 씬 파일 형식
- 첫 인자는 **`.cub` 확장자**의 씬 설명 파일.
- **맵 문자는 6종만**: `0`(빈 공간), `1`(벽), `N`/`S`/`E`/`W`(플레이어 시작 위치 및 방향).
- 맵은 **벽으로 완전히 둘러싸여야** 함, 아니면 에러.
- 맵 외 요소는 빈 줄 하나 이상으로 구분 가능. **맵은 항상 마지막**에 위치(맵 외 요소는 임의 순서 가능).
- 맵 외 요소 정보는 공백 하나 이상으로 구분 가능. **맵은 파일에 보이는 그대로 파싱**(공백도 맵의 유효한 일부 — 직접 처리).
- 요소는 식별자로 시작, 엄격한 순서로:
  - `NO <북쪽 텍스처 경로>`, `SO <남쪽>`, `WE <서쪽>`, `EA <동쪽>`
  - `F R,G,B` (바닥 색, 각 [0,255])
  - `C R,G,B` (천장 색, 각 [0,255])
- 어떤 종류든 잘못된 설정이 발견되면 프로그램은 깔끔하게 종료하고 **`Error\n`** + 본인이 정한 명시적 에러 메시지 출력.

## 4. Bonus part

> mandatory가 **완벽**할 때만 평가(잘못된 사용에도 실패 없어야 함). mandatory 만점이 아니면 보너스 전부 무시.

- 벽 충돌 처리(wall collisions)
- 미니맵 시스템
- 열고 닫을 수 있는 문(doors)
- 애니메이션 스프라이트(animated sprites)
- 마우스로 시점 회전

> 보너스를 위해 추가 함수 사용·맵에 심볼 추가·씬 파일 형식 변경 허용(평가 시 정당화 가능해야 함).

## 5. 제출 및 평가

- Git 저장소에 제출, 파일명 정확히 확인.
- 평가 중 이해도 검증을 위한 간단한 수정 요청 가능(함수 일부 변경, 표시 수정, 자료구조 조정 등 — 몇 분 내 가능한 수준).
