## 1. 개요

**Pong 콘테스트를 위한 웹사이트**를 만드는 팀 프로젝트. 사용자는 멋진 UI, 채팅, 실시간 멀티플레이어 온라인 Pong 게임을 즐길 수 있어야 한다. (더 이상 C/C++ 아님)

## 2. Mandatory part

### 2.1 Overview (기술 제약)

| 항목 | 요구사항 |
|------|----------|
| 백엔드 | **NestJS** 필수 |
| 프론트엔드 | 자유 선택 **TypeScript 프레임워크** |
| 라이브러리 | 자유 사용, 단 모든 라이브러리·프레임워크는 **최신 안정 버전** |
| 데이터베이스 | **PostgreSQL만** (다른 DB 금지) |
| 앱 형태 | **SPA(단일 페이지 앱)**, 브라우저 뒤로/앞으로 버튼 동작 필수 |
| 브라우저 호환 | 최신 **Google Chrome** + 자유 선택 브라우저 1종 |
| 에러 | 처리되지 않은 에러·경고 없어야 함 |
| 실행 | **`docker-compose up --build` 단일 명령**으로 전체 실행 |

> 클러스터 Linux에서는 보안상 **rootless 모드 Docker** 사용. 런타임 파일은 `/goinfre` 또는 `/sgoinfre`에 위치, 비-root UID 컨테이너에서는 bind-mount 볼륨 사용 불가(대안: VM 내 Docker, 변경 후 재빌드, root UID 이미지 제작).

### 2.2 Security concerns
- DB에 저장되는 **비밀번호는 반드시 해시**(강력한 해싱 알고리즘 사용).
- **SQL 인젝션 방어** 필수.
- 폼·모든 사용자 입력에 대한 **서버 사이드 검증** 구현.
- credential·API 키·env 변수는 **`.env`에 로컬 저장 + git ignore**. 공개 노출 시 프로젝트 실패.

### 2.3 User Account
- **42 인트라넷 OAuth**로 로그인.
- 웹사이트에 표시될 **고유 이름(unique name)** 선택 가능.
- **아바타 업로드** 가능, 미업로드 시 기본 아바타 설정.
- **2단계 인증(2FA)** 활성화 가능(Google Authenticator, 문자 전송 등).
- 다른 사용자를 **친구로 추가**, 친구의 현재 상태(online/offline/in a game 등) 확인.
- 프로필에 **통계**(승패, 래더 레벨, 업적 등) 표시.
- **매치 히스토리**(1v1, 래더 등) 보유, 로그인한 누구나 열람 가능.

### 2.4 Chat
- **채널(채팅방)** 생성: public / private / 비밀번호 보호(protected) 중 선택.
- 다른 사용자에게 **다이렉트 메시지** 전송.
- 다른 사용자 **차단(block)** → 차단한 계정의 메시지 안 보임.
- 채널 생성자는 떠나기 전까지 자동으로 **채널 소유자(owner)**:
  - 채널 접근 비밀번호 설정·변경·제거 가능.
  - 소유자는 채널 **관리자(administrator)**이며 다른 사용자를 관리자로 지정 가능.
  - 관리자는 다른 사용자를 **kick/ban/mute**(일정 시간) 가능, 단 채널 소유자는 대상 불가.
- 채팅 인터페이스에서 **Pong 게임 초대** 가능.
- 채팅 인터페이스에서 **다른 플레이어 프로필 접근** 가능.

### 2.5 Game
- 웹사이트에서 다른 플레이어와 **실시간 Pong 라이브 게임** 플레이.
- **매치메이킹 시스템**: 큐에 참가하면 자동으로 상대 매칭.
- canvas 게임 또는 3D 렌더링 게임 가능, 못생겨도 됨. 단 **원조 Pong(1972)에 충실**해야 함.
- **커스터마이징 옵션**(파워업, 다른 맵 등) 제공. 단 사용자가 추가 기능 없는 **기본 버전**도 선택 가능해야 함.
- 게임은 **반응성(responsive)** 있어야 함.

> 네트워크 이슈(예기치 못한 연결 끊김·랙)를 고려해 최선의 UX 제공.
